# 第一部分 · 为什么这样做

---

## 1. 目标与范围

按日期浏览历史上发生过的有影响力的事件。任意一天可查，不限于今天。
面向 10–18 岁的中文读者，以六年级为设计基准。

### 1.1 做

- 任意日期（含 2/29）的事件时间轴，按年份从早到晚
- 维基编者精选条目（`selected`）置顶，附「为什么重要」
- 难词注音与极短释义，按共享词表渲染
- 自建精选库：航空航天等重点领域、孩子向改写

### 1.2 不做

| 不做 | 原因 |
|---|---|
| 全量历史数据库 | 范围无边界；维基的 366 天已够 |
| 搜索引擎 | 按日期浏览是产品定位，不是检索 |
| 社交分享 | 无用户系统，无后端 |
| **领域分类筛选** | **实测不可靠，见 §5** |
| **👤人物 分类** | **数据源结构上不支持，见 §5.4** |
| 新闻正文入库 | 版权与多语言问题，见 §3.4 |

---

## 2. 实测结论汇总

本节是全文的依据。所有数字来自 `.cache/raw/` 的 **364 天完整数据**
（366 天中 04/12、08/06 遇 `HTTP 504` 待补跑），共 **15,057 条事件**。

> ⚠ v1.x 的多项结论曾由单日（10/09）外推，已被全年数据修正。
> 凡本节与旧版冲突，以本节为准。

### 2.1 数据规模

| 指标 | 实测值 |
|---|---|
| 全年事件总数 | 15,057 条 |
| 每天事件数 | 中位 **39**，均值 41.4，min 16，max 124（07/01）|
| 原始响应体积 | 每天中位 344 KB，max 910 KB，全年 132 MB |
| 每条事件关联维基条目 | 2–6 个；**99.5%** 至少有一个 `wikibase_item` |

### 2.1.1 瘦身后体积（实测三种存储方式）

| 存储方式 | 全年 | 每天中位 |
|---|---|---|
| `{y,t,u}`，无 `links` | 1.8 MB | — |
| **`links` 存条目标题**（采用）| **2.68 MB** | **7 KB**（max 19 KB）|
| `links` 存完整 URL | 3.12 MB | — |

gzip 后约 **0.94 MB**。

**存标题而不存 URL**：完整的 percent-encoded URL 约 84 字节，
而条目标题「诺贝尔和平奖」只有 18 字节 —— **URL 的存储成本是标题的约 5 倍**。
前端用 `'https://zh.wikipedia.org/wiki/' + encodeURIComponent(title)` 还原即可。
附带好处：第 3b 步人工编辑 JSON 时，标题可读，URL 不可读。

**2.7 MB 装得下全年** —— 这个数字解掉大部分矛盾：离线可用、秒开、
可人工改写、可先审内容、不怕 API 变更或限流。

> ⚠ 旧版 §2.1 曾写「1.8 MB」，那是**加入 `links` 字段之前**的测量值，已失效。

### 2.2 繁简混排：全量强制转换

zh.wikipedia 同一条响应里繁简混排。用 85 个繁体专用字做探针，
**364/364 天全部命中**，高频的有 `國發為軍會後爾於開馬聯與華時機議約達對個學將過來當進現導間電`。

受众读简体，所以转换是**阻断级**要求，不是可选项。处理见 §7.1。

### 2.3 可读性：只差 0.7 个百分点

事件原文（已转简体）对照 HanziGo 教材识字量，逐字覆盖率：

| 读者 | 累计识字 | `selected` | `events` | 判断 |
|---|---|---|---|---|
| 10 岁（四年级） | 2439 | 89.9% | 91.0% | ❌ 吃力 |
| **12 岁（六年级）** | **2849** | **94.3%** | **93.8%** | ⚠️ 差一点 |
| 15 岁（九年级） | 3174 | 94.9% | 94.2% | ⚠️ 差一点 |

流畅自读门槛 95%。六年级 94.3%，**只差 0.7 个百分点**，且缺口集中在很少的字上。

**所以不改写全文，只给少数难词加注音。** 这是可读性方案的核心判断。

### 2.4 注释工作量：共享词表是关键

| 指标 | min | 中位 | 均值 | p90 | max |
|---|---|---|---|---|---|
| 每天生字种数 | 23 | 46 | 47.6 | 63 | 90 |
| **每天候选词** | 12 | **28** | 29.1 | 41 | **80** |
| 每天专名（跳过） | 12 | 30 | 31.1 | 44 | 69 |

> 早先按单日手估「每天约 13 个词」，**实测低估约 2 倍**，实为中位 28 个。

**决定性的数字是重复率**：逐日相加 10,604 个候选，去重后仅 **2,335 个**，
重复率 **78%**。分布很陡：

| 注前 N 个高频词 | 覆盖全年出现次数 |
|---|---|
| 50 | 34% |
| 100 | 47% |
| **121** | **50%** |
| 200 | 60% |
| **477** | **75%** |
| 500 | 76% |
| 800 | 83% |
| 1275 | 90% |

另一端，**71%（1,647 个）的词全年只出现 1–2 天**，是不值得预先写的长尾。

高频词：并（301 天）、签署（212）、受伤（211）、成功（203）、坠毁（146）、
宪法（111）、罹难（99）、加冕（77）、颁布（70）、屠杀（52）。

**结论：注释必须是按「词」索引的共享词表**（§6.2），不是挂在每条事件上的
per-day 条目 —— 后者会把「签署」写 212 遍，且无法统一修订。

### 2.5 领域分类：三条路都试过，都不可靠

| 方案 | 实测结果 | 结论 |
|---|---|---|
| 关键词匹配（句子文本） | 62% 落入「其他」 | ❌ |
| 关键词匹配（**条目标题＋文本**） | 40% 落入「其他」，但**多标签 15%**，体育 **95% 误判** | ❌ |
| Wikidata P31/P279 | 机制可行（364 次批量调用），但需手写数百个类映射 | ⏸ 成本在别处 |
| 人工标注高频实体 | 标 1000 个实体才覆盖 63% 事件；71% 实体只出现一次 | ❌ 性价比差 |
| **LLM 预生成打标** | 未实测 | ✅ v1.1，需过准入门槛（§5.5）|

详见 §5。**v1 不做领域筛选。**

### 2.6 航空航天与人物：不能做成 API 驱动的标签页

| 分类 | 全年事件数 | 日均 | 空白天数 |
|---|---|---|---|
| 🚀 航空航天 | 363 | 1.0 | **136/364（37%）** |
| 👤 人物 | 157（且多为误判）| 0.4 | **233/364（64%）** |

- **航空航天**只存在于自建精选库（§3.3）—— 日期由你挑，不指望 API 当天恰好有
- **人物分类删除** —— 原因是结构性的，见 §5.4

## 3. 数据源

### 3.1 API 端点

```
https://api.wikimedia.org/feed/v1/wikipedia/zh/onthisday/{type}/{MM}/{DD}
```

`type` ∈ `selected` | `events` | `births` | `deaths` | `holidays` | `all`

实测体积（10/09、03/15）：

| type | 条数 | 体积 |
|---|---|---|
| `selected` | 5 | 57 KB |
| `events` | 41 | 231 KB |
| `births` | 80 | — |
| `deaths` | 36 | — |
| `all` | 168 | **1217 KB** |

本项目**只取 `selected` 与 `events`**。`births`/`deaths` 是独立端点，
不取 —— 这是 §5.4 删除人物分类的直接原因。

### 3.2 调用约束（实测）

| 约束 | 实测 | 应对 |
|---|---|---|
| CORS | `access-control-allow-origin: *` | 浏览器可直调，但本项目仍预生成 |
| 缓存 | `s-maxage=300, max-age=60`，带 `etag` | — |
| **限流** | **远比「第 11 个请求」严格** —— 服务端是 envoy 令牌桶（`x-envoy-ratelimited: true`），**`retry-after` 实测 13–41 秒**。5s 固定间隔下 10 个请求仍有 3 个被限 | 间隔 5s ＋ **完全听服务端 `retry-after`**，不自己猜退避时长 |
| 共享配额 | 企业 NAT 出口（`x-client-ip` 单一地址），配额与同网段用户共享，实际速率**不可预测** | 必须缓存；重跑免费 |
| 偶发故障 | 全年跑有 2 天返回 `HTTP 504` | 记录失败日期，单独补跑 |
| User-Agent | Wikimedia 政策要求可联系标识 | 必须带 |

### 3.3 两层数据策略

**第一层 · 维基 API**：预生成 366 天，转简体、瘦身后提交进仓库。

**第二层 · 自建精选库** `data/picks/MM-DD.json`：手工整理，放航空航天等重点领域
与孩子向改写。与 API 结果按 `(year, 文本前 12 字)` 去重合并。

失败路径三级回落：

```
API/本地 JSON 读取失败 → 读精选库 → 精选库也无该日 → 明确空状态提示
```

> ⚠ 精选库覆盖「全年重点日期」，不是 366 天全覆盖。
> 所以第三级空状态是**必须实现的真实状态**，不能宣称「不影响使用」。

### 3.4 为什么不接 NYT / BBC（已核实）

曾考虑把《纽约时报》《BBC》作为第二、三数据源，实测后放弃。
**新闻只做外链，不入库。**

| | 实测结果 | 结论 |
|---|---|---|
| **Wikipedia** | 无 key、CORS `*`、CC BY-SA 4.0 | ✅ 唯一可预生成并提交进仓库的源 |
| **NYT Archive API** | 无 key 返回 `HTTP 401`；免费 key 限 2000 次/天 | ❌ 见下 |
| **BBC** | `bbc.co.uk/onthisday` 返回 `302`（老站已下线），只剩当日新闻 RSS | ❌ 无可用接口 |

NYT 的三个问题：

1. **静态站放不了 API key。** 无后端，key 写进 JS 等于公开，且绑个人账号
2. **条款限制存储与再分发。** 该 API 定位是链接与展示，不是建副本。
   元数据＋链接尚可，存正文不行
3. **只有英文。** 受众读中文 —— 这一条先于版权就否决了它

**时间覆盖也不够**：NYT 档案约自 1851 年起，BBC 自 1922 年起，
而实测事件含 622、764、1000、1238 年 —— 绝大部分历史早于这两家的档案。

替代做法：维基做**数据层**（许可证正为此而设）；新闻只做**出站链接**，
近现代事件可指向检索地址或 archive.org 快照 —— 无 key、无条款风险、无维护成本。

## 4. 受众与可读性

**10–18 岁，基准六年级，母语中文，读简体。**
以六年级为准：往下 10 岁的靠注音和「为什么重要」够用，往上中学生直接读原文无碍。

依据见 §2.3（覆盖率 94.3%，门槛 95%）与 §2.4（词表工作量）。

### 4.1 注音规则（可执行，不是"看着难就注"）

把六年级生字分三类，**只注第三类**：

| 类别 | 字例 | 处理 |
|---|---|---|
| **音译专名用字** | 亚亨俄勒康敦曼涅淳狄玛甘禄穆纳翰莎默 | **不注**。「康涅狄格」「穆罕默德」连读即可 |
| **常用高频字** | 仁仍其并限奖撤杀 | **不注**。教材未列，但日常一定见过 |
| **实词难字** | 叙坝奴徙徭暨署赦针隶颁魁魅 | **注音＋极短释义** |

三条规则：

1. **注词不注字** —— 给「徭役」而不是单给「徭」，词比孤字好懂
2. **释义不超过 12 字** —— 这是提示，不是词典
3. **一条事件最多注 3 个** —— 渲染期约束，超出只标最靠前的 3 个。
   若频繁触发，说明该条需人工改写

### 4.2 候选词提取（`survey_notes.py` 已实现）

1. 读 HanziGo `data/grade{1..6}-semester{1,2}.json`，得六年级识字表（2849 字）
2. 扫事件文本，找出不在表内的字
3. **jieba 分词＋词性过滤**排除音译专名：专名整词切出（康涅狄格、穆罕默德、
   珠穆朗玛峰）后按词性丢弃。全年跳过专名 3,871 个
4. **排除常用高频字**：维护小白名单，人工积累
5. 余下按全年出现天数降序输出，人工填拼音与释义

词性过滤解决了前一版的两类错误：不再产生「斯于纳夫普」碎片，也不再误删
奴隶、叙利亚。

两条保留意见：

- **白名单必须人工养。** 成功、完成、使用、影响这类词只因教材识字表未收
  就进了候选，对六年级并不难。这些词应进白名单而**不是**词表 ——
  否则页面会被无意义的注释铺满
- **启发式会漏。** 拿破仑（72 天）作为音译专名漏进了候选 ——
  jieba 对它的词性标注不稳定

⚠ **候选表是给人看的草稿，不直接进产物。**

### 4.3 内容分级（必须）

10 岁和 18 岁能看的内容不一样。10/09 一天之内就有：
屠杀超过 10,000 人、刺杀、处决、核试验。

- 这类事件**不回避**（是真实历史，也是教育内容），但需要**措辞与语境**，
  不能只甩一句「活埋四十多万人」
- 预生成的产物必须**人工过一遍**才上线 —— 实时 fetch 做不到这一点
- 字段 `sensitive: true` 标记需家长陪读的条目，前端可按需弱化

## 5. 领域分类：为什么 v1 不做

8 分类＋关键词引擎是最初方案里最吸引人的部分，也是实测后唯一被整体否决的部分。
本节记录全部证据，避免日后重新提出。

### 5.1 关键词匹配（句子文本）：62% 落入「其他」

全年 15,057 条，按 8 分类关键词匹配事件文本：

| 指标 | 实测 |
|---|---|
| 落入 📌其他 | **9,297 条 = 62%** |
| 多标签命中 | 3.0% |

> 单日抽样曾得 46%，**全年是 62% —— 更差，不是更好**。

根因：API **不提供** `categories`/`topics`/`tags` 字段（已核实），
只能从一句话里猜，而中文事件句常常不含触发词 ——
「法国废除死刑」人一看就是政治，关键词匹配不到。

### 5.2 关键词匹配（条目标题＋文本）：召回改善，精度崩溃

`pages[]` 每条带 2–6 个维基实体（99.5% 覆盖），信号比句子丰富得多：
「北韓…核試驗」同时给出 核试验、核武器、朝鲜民主主义人民共和国。

| 信号 | 落入「其他」 |
|---|---|
| 仅句子文本 | 62% |
| **标题＋文本** | **40%** |

召回确实改善，空白天数也基本消失（政治、军事 0 天空白，体育 3%）。
**但精度崩溃**：

| 问题 | 实测 |
|---|---|
| 多标签 | **15%（2,320 条）** |
| 体育分类误判率 | **95%（1,145/1,203）** |

体育的误判全来自裸子串「队」，它匹配 军队、部队、舰队、探险队、海军陆战队：

> ❌ 「以色列军队撤出西奈半岛」→ `[军事, 体育]`
> ❌ 「拿破仑一世率领的法兰西第一帝国军队…埃劳战役」→ `[政治, 军事, 体育]`
> ❌ 「英国航海家库克率领的船队到达…珊瑚礁」→ `[体育]`

**中文子串匹配没有词边界可依。** 收紧关键词则「其他」立刻回升 ——
两种错误互相交换，没有同时能接受的设置。

更深的问题：两种错误率都随关键词选择大幅摆动。同一天（10/09）、同一份数据，
不同关键词表给出 46% 与 66%，相差 20 个百分点。
**准确率对任意词表编辑如此敏感的方案，无法调到可靠状态。**

### 5.3 Wikidata 路线：机制可行，成本在别处

实测 `wbgetentities` 可取 P31（实例）/P279（子类）：

- 每次批量 50 个 id，全年 **18,163 个实体 = 364 次调用**，离线一次完成 —— 便宜
- **但原始 P31 值粒度太细，无法直接用**：

```
核试验  → P279: Q7978067, Q2656967, Q2739113
清朝    → P31:  Q3624078, Q50068795, Q1089515, Q11042
联合国  → P31:  Q245065, Q484652, Q163740, Q43229
```

要把这些映射到 8 个面向读者的分类，须手写数百个 Wikidata 类的映射表，
再对未映射的沿 P279 子类链上溯。这是数天的本体工程，产物仍需复核。
**成本落在了你想避开的地方。**

更便宜的变体（人工标注高频实体而非其类）也不划算：

| 人工标注实体数 | 事件获得 ≥1 标签 |
|---|---|
| 200 | 40% |
| 1,000 | 63% |
| 5,000 | 83% |

**71% 的实体全年只被链接一次**，没有短头可利用。
标 1,000 个实体换 63%，对比词表「500 词换 76%」性价比明显差。

### 5.4 👤人物分类：结构上不支持，删除

这不是调参问题：

- 全年仅 **1.0%**（157/15,057）的事件提到 出生/逝世/诞辰/去世
- 原因是**生卒是独立 API 端点**（`type=births|deaths`），本项目不取（§3.1）
- 且这 157 条**多为误判** —— 是王位继承事件，不是人物传记：

> 「中国总理周恩来于北京逝世。」
> 「日本皇太子明仁在其父亲昭和天皇因病逝世后，正式即位成为第125代天皇」

第二条是政治继承，被关键词归入人物。**改关键词无法修复**，需换端点。

**决定：从分类体系中删除 👤人物。**
若将来要做，必须作为独立特性去取 `births`/`deaths` 端点
（10/09 实测 80 births、36 deaths，数据量可观），而不是在 `events` 里打标。

### 5.5 v1.1 的 LLM 打标方案与准入门槛

LLM 逐条打标是唯一「像人一样读句子」的方案，且离线运行，前端仍零依赖。
**但不凭信心采用**，须先过门槛：

1. 人工标注 **200 条分层样本**作为基准（跨月份抽取，刻意纳入 §5.2 的难例）
2. 让 LLM 标同一批 200 条
3. **门槛：单标签一致率 ≥85%，多标签比例 ≤5%**
4. 未达标则筛选器不上线；达标后再标全部 15,057 条并上线筛选

门槛数字的来源：关键词方案实测 40% 未分类、15% 多标签，
**这个门槛正是它没过的那条线。**

这 200 条基准值得做：它只是约 200 次判断，可复用于任何未来的打标尝试，
并把「筛选器看着还行」变成一个数字。

### 5.6 v1 的替代设计

| 原方案 | v1 做法 |
|---|---|
| 顶部 8 分类标签栏 | **删除** |
| 底部分类数量统计 | **删除** |
| 按分类筛选 | **删除**，只按年份排序 |
| 🚀 航空航天标签页 | 移入自建精选库（§3.3）|

> **筛掉一半内容的筛选器，比没有筛选器更坏。**
> 点「政治」就永远看不到「长征结束」——
> 用户无法分辨「这天没有政治事件」与「分类器漏了」。

v1 用**年份时间轴**作为唯一组织轴。这恰恰因为筛选被移除而成为正确的默认 ——
时间是这个产品里唯一无歧义、无需推断的维度。

## 6. 数据格式

三类文件：**按天的事件**、**全局词表**、**自建精选库**。
注释不挂在事件上（理由见 §2.4 的 78% 重复率）。

### 6.1 按天事件 `data/otd/MM-DD.json`

```json
{
  "date": "10-09",
  "generated": "2026-10-09",
  "selected": [
    {
      "y": 1807,
      "t": "普鲁士首相施泰因颁布法令，解除农奴对地主的人身依附，停止徭役，史称「十月赦令」。",
      "u": "施泰因",
      "l": ["施泰因", "农奴制", "普鲁士"],
      "why": "农奴过去不能离开土地、要白干活。这道命令让他们第一次成为自由人。",
      "src": "wiki"
    }
  ],
  "events": [ "…同结构，可无 why…" ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `y` | ✅ | 年份，公元前用负数。**API 已提供 `year` 字段**，无需从文本解析 |
| `t` | ✅ | 事件文本，**已转简体**，可人工改写 |
| `u` | ✅ | 主维基条目**标题**（CC BY-SA 要求，见 §9.1）。URL 由前端还原 |
| `l` | — | 关联实体标题数组，来自 `pages[]`，最多 4 个（见 §6.4）|
| `why` | — | 「为什么重要」，给小读者；`selected` 建议都写 |
| `src` | ✅ | `wiki`＝源自维基（受 CC BY-SA）；`own`＝完全自写。决定授权，必填 |
| `sensitive` | — | `true` 表示建议家长陪读（见 §4.3）|
| `notes` | — | **仅例外用**：该条独有、不值得进全局词表的词（见 §6.2 第 4 条）|

**事件对象里没有常规 `notes`** —— 注释查全局词表。
**没有 `tag` 字段** —— v1 不做分类（§5.6）；v1.1 过门槛后再加。

### 6.2 全局词表 `data/glossary.json`

```json
{
  "version": 1,
  "generated": "2026-10-10",
  "words": {
    "签署": { "p": "qiān shǔ", "d": "正式签字生效", "n": 212 },
    "罹难": { "p": "lí nàn",   "d": "遭遇灾祸死亡", "n": 99  },
    "颁布": { "p": "bān bù",   "d": "正式公布",     "n": 70  }
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `p` | ✅ | 拼音，音节间半角空格 |
| `d` | ✅ | 释义，**≤12 字**（§4.1 第 2 条）|
| `n` | — | 全年出现天数，来自 `survey.json`，用于排优先级；非渲染用 |

设计要点：

1. **一次编写、全年复用。** 按 `n` 降序写，121 词到 50%，477 词到 75%，
   不必写满 2,335 个
2. **长尾不预写。** 71% 的词全年只出现 1–2 天。词表里查不到就不注 ——
   前端静默跳过，不报错、不显示空提示
3. **渲染时匹配。** 前端加载 `glossary.json`（实测 500 词 45 KB，gzip 后 3 KB），
   对文本做最长优先匹配，命中加虚下划线。
   ⚠ 匹配必须在 `escapeHtml` **之后**插标记，否则破坏转义（§8.4）
4. **例外仍可 per-event。** 某条独有的生僻词（如古地名）不值得进全局词表，
   可留在该条 `notes` 里。渲染顺序：事件 `notes` 优先，再查全局词表
5. **一条最多 3 个**（§4.1 第 3 条），是渲染期约束

### 6.3 自建精选库 `data/picks/MM-DD.json`

结构同 §6.1，但 `src` 多为 `own`。放航空航天与孩子向改写。
与 API 结果按 `(y, t 前 12 字)` 去重合并，精选库优先。

### 6.4 `l`（关联实体）的来源与用途

实测 `pages[]` 每条事件带 2–6 个维基实体，99.5% 有 `wikibase_item`。
这些实体比单一的 `u` 对小读者有用得多 ——
「北韓…核試驗」关联到 核试验、核武器、朝鲜民主主义人民共和国。

- 预生成时从 `pages[]` 提取**标题**，`opencc` 转简体
- **过滤年份条目**：正则 `^-?\d+年$`、`^\d+年代$`、`^公元前\d+年$`
- 最多留 **4 个** —— 再多在卡片底部一行放不下
- ⚠ **3.4% 的事件过滤后为空** → `l` 省略，`u` 也无，前端不渲染链接行
- 前端把 `t` 中出现的实体名渲染为内链（见 §8.4 的渲染顺序）

**URL 还原规则**（前端）：

```js
const wikiUrl = t => 'https://zh.wikipedia.org/wiki/' + encodeURIComponent(t);
```

⚠ 维基条目标题含 `/` 时（少见，如「AC/DC」）`encodeURIComponent` 会编码为 `%2F`，
维基可正确解析，无需特殊处理。

## 7. 脚本

### 7.1 `scripts/gen_otd.py` — 预生成

遍历 366 天 → 转简体 → 瘦身 → 提取 `links` → 写文件。

| 要求 | 做法 |
|---|---|
| 繁简转换 | `opencc` t2s，**预生成时转**，产物纯简体 → 前端零依赖零开销 |
| ⚠ opencc **非幂等** | 必须**反复转到不动点**。它是词组优先的转换器，一次只解开一层：`《科學怪人》於倫敦` → pass1 `《科学怪人》於伦敦`（「於」未转）→ pass2 `于伦敦`。单次转换后 366 天里 **7 天残留繁体「於」** |
| ⚠ 不动点后仍残留 1 例 | `，於穆鲁罗阿环礁` 永不收敛（opencc 为保护姓氏「於」而不转）。用 `_RESIDUAL` 表强制 `於→于`，**有损修正**，新增语料须重新核验 |
| 限流 | 请求间隔 **≥1s**，对 `429` 指数退避（实测第 11 个请求即限流）|
| 缓存复用 | `events` 复用 `.cache/raw/`（`survey_notes.py` 已建好 364 天），**不再请求** |
| ⚠ `selected` 未缓存 | `survey_notes.py` 只抓了 `events`。`selected` **必须现抓 366 次**，≥1s 间隔 ≈ 7 分钟 |
| `504` 处理 | 记录失败日期并单独补跑（全年实测 04/12、08/06 失败）|
| User-Agent | 带可联系标识（Wikimedia 政策）|
| **幂等** | 重跑**不覆盖**已人工编辑的条目 —— 靠 `src`/`why` 判断，或用 `data/picks/` 覆盖层 |
| 质量扫描 | 扫 `·（` / `·遭` 等人名截断模式并报告（§10.1）|

⚠ 幂等不做好，一次重跑就冲掉几十小时的改写。
共享词表降低了这个风险：`glossary.json` 由人工维护，生成脚本**只读不写**。

**不要在前端转繁简** —— 纯 JS 要带几千条映射表，和「零依赖」冲突。

⚠ `opencc` 只转字形，**不转用词差异**（「公車」→「公车」而非「公交车」）。
专名如「馬拉拉」→「马拉拉」正确，但部分港台译名与大陆惯用不同
（「雪梨」vs「悉尼」），人工校对时留意。

### 7.2 `scripts/survey_notes.py` — 词表候选调查（已实现）

产出 `docs/survey.json`（2,335 词频表）与 `docs/survey.log`。
算法见 §4.2。原始响应缓存在 `.cache/raw/`，重跑不请求 API。

### 7.3 `scripts/sample_for_tagging.py` — v1.1 打标基准（待实现）

抽取 200 条分层样本供人工标注，作为 §5.5 的准入基准。

- 跨 12 个月均匀抽取
- 刻意纳入 §5.2 记录的难例（含「队」「军」子串、多标签误判）
- 输出 `docs/tagging-baseline.json`，含 `text`、`links`、空的 `gold` 字段待人工填

## 8. 前端

### 8.1 技术约束

- 纯 HTML/CSS/JS，**无构建、无框架、无运行时依赖**
- 可 `file://` 直开，也可 GitHub Pages 发布
- 断网可用（读本地 JSON）

### 8.2 交互

| 功能 | 说明 |
|---|---|
| 日期切换 | 月/日下拉选择，含 2/29 |
| 回到今天 | 一键跳回当天 —— ⚠ 用**本地时区**，不是 UTC |
| 精选置顶 | `selected` 标「精选」并显示 `why`；`events` 折叠在下面 |
| 时间轴 | 按年份从早到晚；卡片含年份、文本、维基链接 |
| 注音 | 命中词表的词加浅色虚下划线，**点击/悬浮**显示 `拼音　释义` |
| 空状态 | 日期无数据时给明确提示，不是空白页 |

注音**默认收起** —— 一条最多标 3 个词，常驻显示反而干扰阅读。
移动端用**点击**，不用 hover。

**不做**：领域筛选标签栏、底部分类统计（§5.6）。

### 8.3 安全与无障碍

| 要求 | 做法 |
|---|---|
| XSS | `escapeHtml` 转义**所有** API 文本（第三方内容，当不可信处理）|
| 外链 | `rel="noopener noreferrer"` |
| 无障碍 | 表单控件带 `aria-label`；注音触发元素可键盘聚焦 |
| 键盘 | 日期选择与折叠可键盘操作 |
| 焦点 | `:focus-visible` 可见焦点环 |

### 8.4 渲染顺序（关键）

文本要经过三层处理，**顺序不能错**：

```
原始 t
  ↓ ① escapeHtml        —— 必须最先，杜绝 XSS
  ↓ ② links 内链标记     —— 实体名 → <a>
  ↓ ③ glossary 注音标记  —— 命中词 → <span class="gloss">
  输出 HTML
```

- ① 必须在最前：若先插标记再转义，自己插的标签会被转义成文本
- ② 在 ③ 之前：实体名（朝鲜民主主义人民共和国）通常比词表词长，
  先占位可避免词表匹配切断实体名
- ③ 最长优先匹配。⚠ 重叠词行为待验证：「其后」(60 天) vs 「其」(190 天)，
  见 §14

`js/glossary.js` 实现为**纯函数**（文本＋词表 → 标记位置数组），与 DOM 无关，
便于单独验证。

### 8.5 失败路径

```
读取本地 JSON 失败
  → 读精选库
    → 精选库无该日 → 空状态提示「这一天还没有整理好的事件」
```

若将来加实时 API 调用：超时/429/解析失败 → 同样回落精选库。

界面布局、配色、组件尺寸见 **[`docs/layout.md`](layout.md)**。

## 10. 已知问题

### 10.0 繁简转换的两个陷阱

见 §7.1 表内两行 ⚠。要点：

1. **opencc 不是幂等的** —— 单次 `convert()` 不够，必须循环到不动点
2. **到不动点后仍有 1 例残留**，须用显式替换表修正

实测：加入不动点循环 ＋ 残留表后，366 天 **15,106 条事件 0 繁体残留**。

### 10.1 人名被截断

API 文本偶有人名截断。10/09 的 2012 年那条是：

> 「巴基斯坦社會活動家馬拉拉·（圖）遭到武裝分子刺殺未遂」

姓氏（優素福扎伊）丢了，只剩「馬拉拉·」。该条 `pages` 里只有「2012年」和「塔利班」，
**部分可自动补回** —— 见下。

### 人名补回（实测 24 条中补回 13 条）

全年 `selected` 实测 **24 条截断**（`events` 端点 0 条）。
关联条目 `pages[]` 里常常就有该人物的完整条目：

> 「德国政治人物阿道夫·在监狱中口述完成的著作《我的奋斗》首次出版。」
> `pages: ['阿道夫·希特勒', '我的奋斗']`     ← 全名在这里

`repair_truncated_names()` 的做法：对每个「名·」出现处，在 `pages[]` 标题里
找以「名·」开头且含「·」的条目，**仅在恰好一个候选匹配时**替换。

| 结果 | 条数 |
|---|---|
| ✅ 自动补回 | **13** |
| ⚠ 仍需人工 | **11** |

补不回的三类原因：

| 原因 | 例 |
|---|---|
| `pages[]` 里没有该人物条目 | `马拉拉·（图）遭到…` → pages 只有 `['塔利班']` |
| **译名不一致** | `罗尔德·（图）所率领…` vs pages 的 `罗阿尔·阿蒙森` |
| 截断处在**名字中段**或**连名字都没了** | `凯末尔·` vs `穆斯塔法·凯末尔·阿塔图尔克`；`美国发明家·、等人创立苹果公司` |

⚠ 最后一类（`发明家·、等人`）连「名」都丢了，无前缀可匹配，
只能靠 `u`/`l` 字段（`史蒂夫·乔布斯`、`史蒂夫·沃兹尼亚克`）人工重写。

### 检测正则

须避开**日期型事件名**的误判：

```python
TRUNC_RE = re.compile(r'·(?=（|\(|，|。|、|；|$|遭|于|被|将|率|在)')
```

| 文本 | 判定 |
|---|---|
| `马拉拉·（图）遭到…` | ✅ 命中 —— 真截断 |
| `哈尔滨市道外区「1·2」火灾` | ⛔ 不命中 —— 日期型事件名 |
| `史称8·10事件` | ⛔ 不命中 |
| `3·13反日运动` | ⛔ 不命中 |

⚠ 初版正则 `·（|·\s*遭|·\s*$` 会漏掉大部分真截断。
实测全年 15,106 条 `events` **0 命中** —— 截断**只出现在 `selected`**。

### 10.2 繁简转换不覆盖用词差异

见 §7.1 末的 `opencc` 说明。

### 10.3 两天数据缺失

04/12 与 08/06 在全年跑中返回 `HTTP 504`，`.cache/raw/` 里没有这两天。
需单独补跑。

### 10.4 白名单与词表的边界未定

成功、完成、使用、影响这类「教材未收但不难」的词，判断标准还没定。
见 §14。

独立仓库，GitHub Pages 发布。

```
on-this-day/

├── css/style.css
├── js/
│   ├── api.js              取数（本地 JSON → 精选库回落）
│   ├── glossary.js         词表加载 ＋ 最长优先匹配（纯函数）
│   ├── render.js           只改 DOM
│   └── app.js              事件绑定
├── data/
│   ├── otd/MM-DD.json      预生成 366 天（已转简体）
│   ├── glossary.json       共享词表（人工维护，脚本只读）
```
