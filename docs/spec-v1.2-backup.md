# 「历史上的今天」功能规格书

**版本**: 1.2.0（全年工作量已实测；注释改为共享词表模型）
**日期**: 2026-10-10
**项目路径**: `chinese/on-this-day/`（独立仓库，与 hanzi-go、qinshihuang 并列）
**受众**: 10–18 岁，**基准六年级**；母语中文、读简体
**形态**: 纯前端单页，无后端
**数据源**: Wikimedia On This Day API ＋ 自建精选库（新闻只做外链，不入库）

---

## 一、目标

按日期浏览历史上发生过的有影响力的事件。任意一天可查，不限于今天。

**不做**：不做全量历史数据库，不做搜索引擎，不做社交分享。

---

## 二、受众与可读性

**10–18 岁，基准六年级，母语中文，读简体。**
以六年级为准：往下 10 岁的靠注音和「为什么重要」够用，往上中学生直接读原文无碍。

### 2.1 实测：六年级读原文有多难

事件原文（已转简体）对照 HanziGo 教材识字量，逐字覆盖率：

| 读者 | 累计识字 | `selected` | `events` | 判断 |
|---|---|---|---|---|
| 10 岁（四年级） | 2439 | 89.9% | 91.0% | ❌ 吃力 |
| **12 岁（六年级）** | **2849** | **94.3%** | **93.8%** | ⚠️ 差一点 |
| 15 岁（九年级） | 3174 | 94.9% | 94.2% | ⚠️ 差一点 |

流畅自读门槛 95%。六年级 94.3% —— **只差 0.7 个百分点**，
而缺口集中在很少的字上：`selected` 5 条里只有 **7 个生字**（亚杀署诞谴责针），
`events` 41 条里 39 个。

**所以不需要改写全文，只要给少数字加注音。** 这是本规格书的核心判断。

### 2.2 注音规则（可执行，不是"看着难就注"）

把六年级生字分成两类，**只注第二类**：

| 类别 | 字例（取自 10/09 实测） | 处理 |
|---|---|---|
| **音译专名用字** | 亚亨俄勒康敦曼涅淳狄玛甘禄穆纳翰莎默 | **不注**。「康涅狄格」「穆罕默德」连读即可，不识字不影响懂句意 |
| **常用高频字** | 仁仍其并限奖撤杀 | **不注**。教材未列，但日常一定见过 |
| **实词难字** | 叙坝奴徙徭暨署赦针隶颁魁魅 | **注音＋极短释义** |

规则三条：

1. **注词不注字** —— 给「徭役」而不是单给「徭」，词比孤字好懂
2. **释义不超过 12 字** —— 这是提示，不是词典
3. **一条事件最多注 3 个** —— 超过 3 个说明该条本身太难，应当改写或不收

### 2.3 全年实测：工作量与「注一次、全年复用」

早先按 10/09 一天手估「每天约 13 个词」，**实测后发现低估了约 2 倍**。
`scripts/survey_notes.py` 跑完全年（366 天中成功 364 天，04/12 与 08/06 遇
`HTTP 504` 需补跑），用 jieba 分词＋词性过滤重做了候选词提取：

| 指标 | min | 中位 | 均值 | p90 | max |
|---|---|---|---|---|---|
| 每天事件数 | 16 | **39** | 41.4 | 57 | 124 |
| 每天生字种数 | 23 | 46 | 47.6 | 63 | 90 |
| **每天候选词** | 12 | **28** | 29.1 | 41 | **80** |
| 每天专名（按规则跳过） | 12 | 30 | 31.1 | 44 | 69 |

词性过滤解决了前一版的两类错误：专名现在整词切出（康涅狄格、穆罕默德、
珠穆朗玛峰）并按词性丢弃，不再出现「斯于纳夫普」这类碎片，也不再误删
奴隶、叙利亚。全年按规则跳过专名 3871 个，与保留的候选量级相当。

**决定性的数字是重复率。** 逐日相加 10604 个候选，**去重后只有 2335 个**
—— 重复率 78%。而且分布很陡：

| 注前 N 个高频词 | 覆盖全年出现次数 |
|---|---|
| 50 | 34% |
| 100 | 47% |
| 200 | 60% |
| **500** | **76%** |
| 800 | 83% |
| 1275 | 90% |

精确地说：**121 个词覆盖一半，477 个词覆盖四分之三。**
另一端，71%（1647 个）的词全年只出现在 1–2 天，是不值得预先写的长尾。

高频词正是预料中的那些：并（301 天）、签署（212）、受伤（211）、成功（203）、
坠毁（146）、宪法（111）、罹难（99）、加冕（77）、颁布（70）、屠杀（52）。

**结论：注释必须是一份按「词」索引的共享词表，不是挂在每条事件上的
per-day 条目。** 写 500 个词覆盖全年四分之三，是一两个晚上的事，不是几个月。
这直接改变了 §5.1 的数据结构（见 §5.2）。

两条保留意见：

- 部分高频「候选」对六年级其实不难 —— 成功、完成、使用、影响
  只是因为教材识字表里没有才被标出。§5.4 第 4 步的白名单**必须人工养**，
  不能全靠自动结果
- 拿破仑（72 天）作为音译专名漏进了候选 —— jieba 对它的词性标注不稳定，
  词性过滤并非万无一失

全量明细在 `docs/survey.json`（2335 词频表）与 `docs/survey.log`。
脚本把原始响应缓存在 `.cache/raw/`，重跑不再请求 API。

### 2.4 内容分级（必须）

10 岁和 18 岁能看的内容不一样。10/09 一天之内就有：
屠杀超过 10,000 人、刺杀、处决、核试验。

- 这类事件**不回避**（是真实历史，也是教育内容），但需要**措辞与语境**，
  不能只甩一句「活埋四十多万人」
- 预生成的产物必须**人工过一遍**才上线 —— 实时 fetch 做不到这一点，
  这是预生成的第二个理由（第一个是可改写）
- 字段 `sensitive: true` 标记需要家长陪读的条目，前端可按需弱化

## 三、数据源

### 3.1 API

```
https://api.wikimedia.org/feed/v1/wikipedia/zh/onthisday/{type}/{MM}/{DD}
```

`type` ∈ `selected` | `events` | `births` | `deaths` | `holidays` | `all`

实测（2026-10-09，10/09 与 03/15）：

| type | 条数 | 体积 |
|---|---|---|
| `selected` | 5 | 57 KB |
| `events` | 41 | 231 KB |
| `all` | 168 | **1217 KB** |

- `access-control-allow-origin: *` —— 浏览器可直接调，无需后端
- `cache-control: s-maxage=300, max-age=60`，带 `etag`
- **会限流**：连续请求第 11 个返回 `HTTP 429`。预生成脚本必须加间隔与重试
- 必须带 `User-Agent`（Wikimedia 政策要求可联系的标识）

### 3.2 `selected` 就是「有影响力」

`selected` 是维基编者自己挑的当日最值得一提的 5 条。
**直接用它，不要自己造重要性排序。** 10/09 的 5 条是马拉拉遇刺、朝鲜首次核试、
万国邮政联盟成立、1740 巴达维亚屠杀、《训民正音》出版 —— 这个水准自己排不出来。

页面上 `selected` 置顶并标记，`events` 折叠在下面。

### 3.3 自建精选库

手工整理，`data/picks/MM-DD.json`，覆盖航空航天等重点领域与孩子向改写。
与 API 结果按 `(year, 文本前 12 字)` 去重合并。API 挂了只显示精选库，不白屏。

### 3.4 为什么不接 NYT / BBC（已核实）

曾考虑把《纽约时报》《BBC》作为第二、第三数据源，实测后放弃。**新闻只做外链，不入库。**

| | 实测结果 | 结论 |
|---|---|---|
| **Wikipedia** | 无 key、CORS `*`、CC BY-SA 4.0 | ✅ 唯一可预生成并提交进仓库的源 |
| **NYT Archive API** | 无 key 返回 `HTTP 401`；免费 key 限 2000 次/天 | ❌ 见下 |
| **BBC** | `bbc.co.uk/onthisday` 返回 `302`（老站已下线），只剩 RSS（当日新闻，非历史档案） | ❌ 根本没有可用接口 |

NYT 的三个问题：

1. **静态站放不了 API key。** 本项目无后端，key 写进 JS 就等于公开，且绑定个人账号。
   只能"仅预生成、key 留在本地"，不能浏览器实时调。
2. **条款限制存储与再分发。** 该 API 的定位是链接与展示，不是让你建自己的副本。
   把标题预生成进公开仓库，正是其归属指引与条款要限制的用法。
   元数据＋链接尚可，存正文不行。
3. **只有英文。** 受众读中文 —— 这一条其实先于版权就否决了它。

还有时间覆盖的问题：NYT 档案约自 1851 年起，BBC 自 1922 年起。
而 10/09 实测事件里有 622、764、1000、1238 年 —— **绝大部分历史早于这两家的档案**。

替代做法（沿用原方案「延伸阅读」的思路）：
- 维基百科做**数据层**，预生成、提交进仓库 —— 许可证正为此而设
- 新闻只做**出站链接**，不存内容：近现代事件可指向检索地址或 archive.org 快照，
  无 key、无条款风险、无维护成本
- 自建精选库放航天与孩子向改写 —— 完全是自编内容

## 四、三项关键处理

### 4.1 繁简转换（阻断级）

zh.wikipedia **同一条响应里繁简混排**。10/09 的 5 条 `selected` 里含
`來務協國圖導屠後會業殺爾版瑞稱簽約編署聯華萬裝裡規訓試誕語調諺譴責這進遂過達郵針鏡開際韓馬驗鮮` ——
转换前 42% 的不同字是繁体。受众读简体，所以这是**全量强制**，不是可选项。

- **预生成时转**（`opencc` t2s），产物是纯简体 → 前端零依赖、零开销
- 不要在前端转：纯 JS 要带几千条映射表，和「零依赖 500 行」冲突
- 验收时抽查 12 天，确认无繁体残留（见第十节）

⚠ `opencc` 只转字形，**不转用词差异**（「公車」→「公车」而非「公交车」）。
专名如「馬拉拉」→「马拉拉」正确，但部分港台译名与大陆惯用译名不同
（如「雪梨」vs「悉尼」），这类需人工校对时留意。

### 4.2 领域分类：不要用关键词引擎

按原方案的 8 分类＋示例关键词实测 10/09 全部 41 条：
**19 条（46%）落进「📌其他」**，且多标签命中 **0**。落榜的是：

> Google 收购 YouTube、长征结束、耶鲁大学建校、开普勒超新星爆发、
> 瓦伊昂大坝溃决（约两千人死亡）、珠峰新测高程

根因：API **不提供** `categories`/`topics`/`tags` 字段（已核实），只能从一句话里猜，
而中文事件句常常不含触发词 ——「法国废除死刑」人一看就是政治，关键词匹配不到。

后果比"分得不准"更糟：点 🏛️政治 就永远看不到「长征结束」。
**筛掉一半内容的筛选器，比没有筛选器更坏。**

替代方案，按推荐顺序：

1. **v1 不做领域筛选**，只按年份排序 —— 诚实且零风险
2. 预生成时用 LLM 逐条打标签，结果写进 JSON（离线一次，前端仍零依赖）
3. 用响应里已有的 `wikibase_item` 查 Wikidata 取真实分类（准，但每条多一次请求）

### 4.3 航空航天不能做成 API 驱动的标签页

抽样 10 天实测：**418 条事件里航天类 15 条（3.6%），平均每天 1.2 条**，
其中 01/15、08/08、10/09 三天为 **0**。

所以 🚀 标签页大多数日子是空的。航空航天应当**只存在于自建精选库**里 ——
日期由你挑，内容由你写，而不是指望 API 当天恰好有。

## 五、预生成（本项目的基础架构，不是可选优化）

受众已定为 10–18 岁，所以预生成是**必须**的：要人工改写、要加难词注释、
要先审内容（见 2.4）—— 这三件事实时 fetch 都做不到。

只保留必要字段即可大幅瘦身。实测 03/15：

```
原始 all        1256 KB
瘦身 sel+events    6 KB      ← 只留 {year, text, url}
→ 366 天全量     2.1 MB      (gzip 约 0.7 MB)
```

**2.1MB 装得下全年。** 这一个数字解掉了大部分矛盾：离线可用、
秒开、可人工改写、可先审内容、不怕 API 变更或限流。

### 5.1 数据格式

两个文件配合：**按天的事件文件**，与**全局共享的词表**。
注释不挂在事件上（理由见 §2.3 的 78% 重复率与 §5.2）。

`data/otd/MM-DD.json`：

```json
{
  "date": "10-09",
  "generated": "2026-10-09",
  "selected": [
    {
      "y": 1807,
      "t": "普鲁士首相施泰因颁布法令，解除农奴对地主的人身依附，停止徭役，史称「十月赦令」。",
      "u": "https://zh.wikipedia.org/wiki/施泰因",
      "why": "农奴过去不能离开土地、要白干活。这道命令让他们第一次成为自由人。",
      "tag": "政治",
      "src": "wiki"
    }
  ],
  "events": [ "...同结构，可无 why..." ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `y` | ✅ | 年份，公元前用负数 |
| `t` | ✅ | 事件文本，**已转简体**，可人工改写 |
| `u` | ✅ | 维基条目链接（CC BY-SA 要求，见 8.1） |
| `why` | — | 「为什么重要」，给小读者；`selected` 建议都写 |
| `tag` | — | 领域标签，预生成时打（见 4.2） |
| `src` | ✅ | `wiki`＝源自维基（受 CC BY-SA）；`own`＝完全自写。决定授权，必填 |
| `sensitive` | — | `true` 表示建议家长陪读（见 2.4） |
| `notes` | — | **仅例外用**：该条独有、不值得进全局词表的词（见 §5.2 第 4 条） |

事件对象里**不再有常规 `notes`** —— 注释查全局词表。

`data/glossary.json`（全局共享，按词索引）：

```json
{
  "version": 1,
  "generated": "2026-10-10",
  "words": {
    "颁布": { "p": "bān bù",   "d": "正式公布",         "n": 70  },
    "徭役": { "p": "yáo yì",   "d": "官府强派的无偿劳动", "n": 1   },
    "赦令": { "p": "shè lìng", "d": "免罪的命令",       "n": 2   },
    "签署": { "p": "qiān shǔ", "d": "正式签字生效",     "n": 212 },
    "罹难": { "p": "lí nàn",   "d": "遭遇灾祸死亡",     "n": 99  }
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `p` | ✅ | 拼音，音节间半角空格 |
| `d` | ✅ | 释义，**≤12 字**（见 2.2 第 2 条） |
| `n` | — | 全年出现天数，来自 `survey.json`，用于排优先级；非渲染用 |

上例里 徭役（1 天）、赦令（2 天）属 §5.2 第 2 条的长尾，本不该预先写；
列在这里只是沿用 10/09 那条事件作示例。实际应从 签署（212）、罹难（99）
这类高频词开始填。

### 5.2 共享词表（为什么不是 per-day）

§2.3 的实测给了两个硬约束：去重后只有 2335 个词，重复率 78%。
per-day `notes` 会把「签署」写 212 遍 —— 不只是浪费，而是 212 份可能互相矛盾、
且无法统一修订的释义。

设计要点：

1. **一次编写、全年复用。** 按 `survey.json` 的 `n` 降序写，
   121 个词到 50%，477 个到 75%，不必写满 2335 个
2. **长尾不预写。** 71% 的词全年只出现 1–2 天。词表里查不到就不注 ——
   前端对缺失词静默跳过，不报错、不显示空提示
3. **渲染时匹配。** 前端加载 `glossary.json`（实测 500 词约 45 KB，gzip 后 3 KB），
   对事件文本做最长优先的词匹配，命中则加虚下划线。
   注意：匹配必须在 `escapeHtml` **之后**插标记，否则会破坏转义（见第七节）
4. **例外仍可 per-event。** 某条独有的生僻词（如某个古地名）不值得进全局词表，
   可留在该条的 `notes` 里。渲染顺序：事件 `notes` 优先，再查全局词表
5. **「一条最多 3 个」仍然有效**（§2.2 第 3 条），但现在是**渲染期的约束**：
   一条事件命中超过 3 个词时，只标注最靠前的 3 个。
   若频繁触发，说明该条需要人工改写

⚠ **白名单必须人工养。** 成功、完成、使用、影响这类词只因教材识字表未收
就进了候选，对六年级并不难。这些词应当进 §5.4 第 4 步的白名单而**不是**词表 ——
否则页面会被无意义的注释铺满。

### 5.3 生成脚本

`scripts/gen_otd.py`：遍历 366 天 → 转简体（`opencc` t2s）→ 瘦身 → 写文件。

- 请求间隔 **≥1s**，对 `429` 指数退避重试（实测第 11 个请求就限流）
- 复用 `.cache/raw/` 的原始响应，已缓存的日期不再请求（`survey_notes.py` 已建好缓存）
- 处理 `504`：全年实测时 04/12 与 08/06 遇 `HTTP 504`，需单独补跑
- 带可联系的 `User-Agent`（Wikimedia 政策）
- **幂等**：重跑不覆盖已人工编辑过的条目 —— 靠 `src`/`why` 是否存在判断，
  或另存 `data/picks/` 覆盖层。⚠ 这一点不做好，一次重跑就冲掉几十小时的改写
  （共享词表把这个风险降低了：`glossary.json` 由人工维护，生成脚本**只读不写**）
- 扫描 `·（` / `·遭` 等人名截断模式并报告（见第九节）

### 5.4 生字候选自动标注（辅助人工）

`scripts/survey_notes.py` 已实现，用于产出词表候选，人工只做取舍：

1. 读 HanziGo `data/grade{1..6}-semester{1,2}.json`，得六年级识字表（实测 2849 字）
2. 扫事件文本，找出不在表内的字
3. **jieba 分词＋词性过滤**排除音译专名：专名整词切出（康涅狄格、穆罕默德、
   珠穆朗玛峰）后按词性丢弃。这比前一版的「连续生字串」启发式准得多 ——
   不再产生「斯于纳夫普」碎片，也不再误删奴隶、叙利亚
4. **排除常用高频字**：维护一个小白名单（仁仍其并限奖撤杀…），人工积累
5. 余下的按全年出现天数降序输出，人工填拼音与释义，写进 `data/glossary.json`

全年实测结果见 §2.3：每天中位 28 个候选，去重后全年 2335 个。

⚠ 第 3、4 步仍是启发式。拿破仑（72 天）就作为专名漏进了候选 ——
jieba 对它的词性标注不稳定。**候选表是给人看的草稿，不直接进产物。**

## 六、交互

- 月/日下拉选择；「回到今天」按钮
- `selected` 置顶（标「精选」）并显示 `why`；`events` 折叠在下面
- 时间轴按年份从早到晚；卡片含年份、文本、维基链接
- **注音呈现**：命中全局词表的词在文本中加浅色虚下划线，
  点击/悬浮显示 `拼音　释义`。移动端用点击，不用 hover
- 日期无数据时给明确空状态，不是空白页

注音不要默认全部展开 —— 一条事件最多标 3 个词（§5.2 第 5 条），
常驻显示反而干扰阅读。

领域筛选与底部分类统计 **v1 不做**（见 4.2）。

## 七、技术约束

- 纯 HTML/CSS/JS，无构建、无框架、无运行时依赖
- `escapeHtml` 转义所有 API 文本（第三方内容，必须当不可信处理）
- 外链 `rel="noopener noreferrer"`
- 表单控件 `aria-label`；若将来加筛选，按钮带 `role` / `aria-checked`
- 失败路径：API 超时/429/解析失败 → 回落精选库 → 仍无数据 → 空状态提示

## 十一、项目结构（规划）

与 hanzi-go、qinshihuang 一致：纯静态、无构建、可 `file://` 直开，
独立仓库，GitHub Pages 发布。

```
on-this-day/
├── index.html          单页：日期选择 ＋ 时间轴
├── css/style.css
├── js/
│   ├── api.js          取数（API → 精选库回落）
│   ├── glossary.js     加载词表 ＋ 文本最长优先匹配（见 5.2）
│   ├── render.js       只改 DOM
│   └── app.js          事件绑定
├── data/
│   ├── otd/MM-DD.json  预生成的 366 天（已转简体）
│   ├── glossary.json   共享难词表（人工维护，生成脚本只读）
│   └── picks/MM-DD.json 自建精选库（航天、孩子向改写）
├── scripts/
│   ├── gen_otd.py      预生成脚本（≥1s 间隔，429 退避，复用 .cache/raw/）
│   └── survey_notes.py 词表候选调查（已实现，见 5.4）
├── docs/
│   ├── spec.md         本文件
│   ├── survey.json     全年 2335 词频表
│   └── survey.log      全年调查日志
├── .cache/raw/         API 原始响应缓存（.gitignore）
├── .nojekyll           GitHub Pages
├── .gitignore
├── LICENSE
└── README.md
```

JS 分文件照 hanzi-go 的分法（取数 / 渲染 / 事件分开）。
词表匹配单独放 `glossary.js`：它是纯函数（文本＋词表 → 标记位置），
与 DOM 无关，便于单独验证。不需要 state.js 那一层。

**命名**：目录与仓库名用 `on-this-day`（带连字符）。
Wikimedia 的路径段写作 `onthisday` 只是因为 URL path 习惯不用连字符，
不作为命名风格参考；`hanzi-go` 已经是连字符风格。

## 十二、实施顺序

分三步，每步都能单独交付、单独验收。

| 步 | 做什么 | 产出 | 验收 |
|---|---|---|---|
| **1** | `gen_otd.py` 抓 366 天、转简体、瘦身（词表候选 `survey_notes.py` 已跑完） | `data/otd/*.json` | 无繁体残留、幂等可重跑 |
| **2** | 单页：日期选择 ＋ 时间轴 ＋ `selected` 置顶 ＋ 词表匹配与注音交互 | `index.html` 等 | 任意日期可查、断网可用 |
| **3a** | 写共享词表：按 `survey.json` 频次降序填前 500 词 | `data/glossary.json` | 覆盖全年 76% 出现次数 |
| **3b** | 人工过内容：写 `why`、标 `sensitive` | 编辑后的 JSON | 可读性与合规两组勾完 |

第 1、2 步是工程，可一次做完。

**第 3a 步是一次性的、有明确终点的**，这是共享词表相对 per-day 注释的主要好处：
按 `docs/survey.json` 的频次降序填，121 词到 50%、477 词到 75%、1275 词到 90%。
写 500 个词是一两个晚上的事，而且写完全年都不用再写。
可以分批 —— 先填前 100 个（覆盖 47%），页面立刻可用，词表里没有的词静默跳过。

**第 3b 步才是长期的**，366 天不必一次写满。先把最近一个月和几个重点日期写好，
其余留 `why` 缺省，页面照常工作。
